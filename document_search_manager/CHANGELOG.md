# Document Search Manager — CHANGELOG

## VERSION 20260903_06

一覧の列構成を見直し、文書の保管フォルダを1行で把握できるようにした。

### 追加

- **「フォルダ」列を「サイト」列の右に追加**した。各文書が**サイト内のどのフォルダに
  保管されているか**を1行で示し、クリックするとそのフォルダが開く。
  - 表示は `Shared Documents/2026/Reports` のような階層パス（URL符号は復号して表示）。
  - リンク先は SharePoint がフォルダを開くときの標準形式
    `<ライブラリ>/Forms/AllItems.aspx?id=<サーバー相対パス>` を組み立てる。
  - Excel / CSV にも「フォルダ」「フォルダリンク」の2列を追加した。

### 変更

- **検索結果に混在するフォルダを「除外」ではなく「区別」する方式にした。**
  - 当初はフォルダを一覧から外す方針だったが、**フォルダ名にキーワードが含まれる一方で
    中のファイルには含まれないケースでは、フォルダの存在そのものが手がかりになる**
    という指摘を受けて方針を変更した（案A）。
  - フォルダ行は**種別列に「フォルダ」と表示**する。既存の種別フィルタ（複数選択）で
    「ファイルだけ」「フォルダだけ」を切り替えられる。
  - フォルダ行のタイトルをクリックすると、そのフォルダが開く。
  - フォルダ行は**一括ダウンロードの対象外**（チェックボックスを無効化。
    見出しの全選択もフォルダを選ばない。サーバー側でも対象から除く）。
  - `config.json` の `exclude_folders`（既定 `false`）を `true` にすると、
    従来案どおりフォルダを一覧から除外できる。
  - フォルダ判定は `fields.isDocument` → `fields.contentclass` → URL末尾の拡張子の
    有無、の順で行う。
- **Document Number 列を画面と出力の両方から外した。** Enovia でのみ必要な項目のため。
  データ自体（`SearchResult.document_number`）は保持しており、Phase 3 で復活させる。
- **件数プルダウンの初期値を常に「上位 10 件」にした。**
  - 従来は `config.json` の `default_max_results` を初期値にしていたため、
    古い設定（100）が残っている環境では 100 件が初期選択されていた。
  - 初期値は静的に10件とし、**前回の作業状態がある場合はそちらを優先**する
    （状態の保持機能があるため、実際に使った件数が次回も再現される）。
  - `default_max_results` は、APIで件数指定が無かった場合のサーバー側の既定値として残す。

### 変更しないこと（宣誓）

- 認証処理（`GraphAuthManager` / `_load_config`）には一切手を入れていない。
- Graph呼び出し・ページング・並列実行・重複排除の各ロジックは変更していない。
- 旧バージョン `_20260903_05.py` は削除せず `old/` へ移動して保持する。

## VERSION 20260903_05

一覧の操作性を大幅に強化し、旧バージョンの自動整理と作業状態の保持を追加した。

### 追加

- **既定の取得件数を10件に変更**した（`DEFAULT_CFG` と `config.example.json` の両方）。
  `config.json` が無い環境でも10件で起動する。
- **旧バージョンの自動アーカイブ**（`_archive_old_versions`）。起動時に、自分より古い
  `document_search_manager_YYYYMMDD_NN.py` を同じフォルダ内の `old/` へ移動する。
  フォルダ直下には最新版だけが残る。
  - 自分自身と、自分より**新しい**版は移動しない（旧版を起動したときに新版を
    退避させてしまわないため）。
  - `old/` に同名がある場合は上書きせず、手元のファイルも消さない。
  - 移動に失敗しても起動は止めない。
  - **Git運用との整合**：リポジトリ側でも `_01`〜`_04` を `old/` へ移動済み。
    これによりローカルの自動移動とリポジトリの構成が一致し、`git pull` で
    旧版が復活して重複することがない。過去バージョンは `old/` から取得できる。
- **列ごとの昇順・降順ソート**。列見出しをクリックするたびに
  昇順（▲）→降順（▼）→解除、と切り替わる。空欄の行は常に末尾へ寄せる。
- **列ごとの絞り込み**。見出し右の「⋮」ボタンで絞り込みパネルを開く。
  - **最終更新日**は「この日以降」「この日以前」の**日付範囲指定**（片方だけの指定も可）。
  - **それ以外の列**（ソース / Document Number / タイトル / 作成者 / 種別 / サイト）は
    **チェックボックスによる複数選択**。例：種別で `pptx` と `xlsm` の両方を選ぶ、など。
    候補には件数を併記し、候補が多い場合は絞り込み用の入力欄で探せる。
  - 絞り込みが効いている列は「⋮」がアクセント色になる。
  - 「フィルタ・ソート解除」ボタンで一括解除できる。
  - 件数表示は「検索結果: 50 件（絞り込み後 12 件）」のように両方を示す。
- **タイトル列と作成者列の間に選択チェックボックス列**を追加し、
  **複数ファイルの一括ダウンロード**（ZIP）を可能にした。
  - 見出しのチェックボックスで、表示中の行をまとめて選択／解除できる。
  - Graph の `/shares/{token}/driveItem/content` で取得する。
    使用スコープは `Sites.Read.All` のままで、**新規権限は不要**。
  - 一部のファイルが取得できなかった場合も全体を失敗させず、取得できた分を返し、
    ZIP内に `_ダウンロード失敗一覧.txt`（タイトル・URL・理由）を同梱する。
  - ZIP内でファイル名が重複する場合は連番を付けて区別する。
  - 1回の上限は `max_download_files`（既定50件）。超過分は失敗一覧に記録する。
- **作業状態の保存と復元**。ツールを終了して再起動しても、前回の
  **検索キーワード・検索対象・取得件数・並び順・絞り込み条件**が復元される。
  - 状態は `session_state.json` に保存する。`restore_last_search` で無効化できる。
  - **検索結果そのものは保存しない**。古い結果を見せないよう、復元時に自動で再検索する。
  - 選択チェックボックスの状態は復元しない（誤って古い選択のまま
    ダウンロードすることを避けるため）。
- **Excel / CSV 出力が、画面の絞り込み・並び順をそのまま反映**するようになった
  （従来は常に全件・取得順だった）。

## VERSION 20260903_02

実機（会社PC）での初回起動時に発生した2件の不具合を修正。

### 修正

- **起動バッチの文字化けエラー**
  `run_document_search_manager.bat` の日本語コメントがUTF-8で保存されていたため、
  Windowsのコマンドプロンプト（CP932）が解釈できず、
