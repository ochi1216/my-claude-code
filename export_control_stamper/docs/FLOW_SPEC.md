# フロー仕様 — ECS01_Stamp_On_Approval_Mail_DEV

`flows/build_flows_20261006_01.py` が生成するフローの設計書。コピペ用の式はここには
置かない(生成側が持つ)。**なぜそうなっているか**を残すための文書である。

## 目的と範囲

手作業の流れ(メール → リンク → 添付のExcel → 印影を挿入 → 保存)のうち、
**印影の挿入と、結果の通知まで**を自動化する。

- 自動でやること: 承認依頼メールの検知、リクエストIDの取得、証明書の添付の特定、
  作業コピーの作成、印影の挿入、位置の検証、(本番のみ)添付の差し替え、記録、通知
- 人がやること: **最終承認ボタンの押下**、コメントの入力、結果の目視確認
- やらないこと: 承認の代行(Approvals コネクタに他人の承認を代行するアクションが無い、と
  認識している。**未確認**)。承認は取り消しにくく、内部統制上も人の判断を残す

## 全体の流れ

```
[Outlook] 新しいメール(件名 [Approval request] 該非判定…, 送信元 flow-noreply@microsoft.com)
   │
   ▼ SCOPE_Main  ─────────────────────────────────────────────────────────────
   │  1. 検証   CHK_Valid_Mail     送信元・件名を再確認 ── 不一致 → 静かに終了(失敗にしない)
   │  2. 解析   CHK_Link_Found     本文にリンクがあるか ── 無い → 通知+記録+失敗終了
   │            CMP_Item_Id        リンクの ID= の数値を取り出す(int()。数字でなければ失敗)
   │  3. 重複   GET_Processed      記録リストに 'ECS-<ID>' かつ 'Done' があるか
   │            CHK_Not_Processed  ある → 通知して成功終了(二重処理の防止)
   │  4. 特定   GET_Attachments    リクエストの添付一覧
   │            FLT_Cert           名前が「…_該非判定証明書.xlsx」で終わるものだけ
   │            CHK_Cert_Single    ちょうど1件 ── 0件・複数 → 通知+記録+失敗終了
   │  5. 複製   GET_Attachment_Content → CREATE_Backup_File(_orig) → CREATE_Work_File
   │            ※ 元の添付は、ここまで一切変更しない
   │  6. 押印   GET_Stamp_Image → RUN_Script(作業コピーに対して)
   │            CHK_Script_Stamped status が 'stamped' か ── 違う → 通知+記録+失敗終了
   │  7. 差替   (本番モード dryRun=false のときだけ生成)
   │            GET_Stamped_Content → DEL_Attachment → ADD_Attachment
   │  8. 記録   LOG_Done            'Done'(dryRun は 'DryRunDone')
   │            NTF_Done            Teams へ通知(押印後のファイルを開くリンク付き)
   ▼
 SCOPE_Catch(SCOPE_Main が Failed / TimedOut のときだけ)
      FLT_Failed_Actions → 失敗したアクション名とメッセージを取り出す
      LOG_Error → NTF_Error(実行履歴へのリンク付き) → END_Failed(必ず失敗で終了)
```

## 設計の理由

### dryRun は「生成時の切替」

実行時に `If` で分岐させず、`dryRun=true` のときは**差し替えのアクション自体を生成しない**。
実行履歴に残るのは、押印した作業コピーだけになる。本番へ切り替えるときは、設定を変えて
生成し直す(生成時に `[本番モード]` と大きく表示する)。安否確認ツールの
`testRecipientOverride` と同じ考え方で、人の操作に安全を依存させない。

### 元のファイルは、差し替えるまで触らない

押印は、作業ライブラリに複製したコピーに対してだけ行う。さらに、複製の前に
`_orig`(退避)を作る。差し替えは「押印が成功と確認できてから」「退避が済んでから」。
差し替え中に失敗しても、元のファイルは `_orig` に残る(通知にもそう書く)。

### 失敗したアクションが分かるようにする

安否確認ツールでは、失敗した枝の名前(例: `CHK_Threshold_Met`)までしか記録できず、
原因の特定に実行履歴を開く必要があった。`result()` はスコープ**直下**のアクションの結果しか
返さないためである。今回は、コネクタのアクションを**すべて SCOPE_Main の直下に並べ**
(スコープの入れ子を作らない)、失敗したアクション名とメッセージを直接取り出す。
`If` の中に置くコネクタは、「通知」と「記録」だけにしてある。

### 止まるときは、先に通知する

`Terminate` は SCOPE_Catch を通らない(安否確認ツールで実測)。検証で止める経路
(リンク無し・処理済み・証明書の添付が1件でない・押印の中止)は、通知と記録を
**自分で行ってから** `Terminate` する。「対象外のメール」だけは、通知せず静かに終える
(コネクタ側の絞り込みをすり抜けた無関係なメールで、毎回通知が来ないように)。

### 二重処理の防止

記録リストに `Title='ECS-<ID>'` かつ `状態='Done'` の行があれば、その ID は処理しない。
`dryRun` の記録は `'DryRunDone'` にして、**dryRun を何度でも試せる**ようにしてある。
Office Script 側でも、押印済みの図形(同名、またはアンカーセルに重なるもの)があれば中止する。
二重の防御である。

### 接続は tenant

メールをきっかけに自動で動くフローは、Request トリガーではないため、`invoker` 接続を使えない
(`InvokerConnectionNotAllowed`。安否確認ツールで実機判明)。接続参照は `tenant` とし、
フローを保存するユーザーの接続を使う。

## 既知の制約・未確認事項

- コネクタの `operationId`・パラメータ名・戻り値の形は未実測(`MEASUREMENT_GUIDE.md`)
- 添付の差し替え(削除 → 追加)の挙動は未実測。添付名が同じで、差し替え後に、依頼側の
  フローや承認の画面から見えるファイルが変わることが前提
- 添付の複製に、数MBを超えるファイルでの制限があるかは未確認(証明書は小さいと想定)
- `Terminate` を `Scope` の中の `If` の枝に置けることは、安否確認ツールで実測済み
- 承認メール本文のリンクの形式は未確認(`requestList.linkMarker`。E3)
- 動作確認は、すべて実機(Windows / Power Automate)で行う。ここ(Linux)でできるのは、
