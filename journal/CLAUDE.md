# CLAUDE.md（journal/ プロジェクト専用）

このファイルは、`journal/`フォルダ内の「学びジャーナル（Journal Manager）」プロジェクトに
限定して適用される、Claude Code Webセッション間の作業引継ぎルールです。
リポジトリの他のフォルダ・他のプロジェクトにはこのルールを適用しません。

このファイルはセッション引継ぎ管理のために追加されたものであり、既存のコード・
`README.md`・`journal/CHANGELOG.md`の内容や役割を変更するものではありません。

## 関連ドキュメント

- `journal/docs/PROJECT_STATUS.md` … プロジェクトの現状（事実ベース、推測を含まない）
- `journal/docs/SESSION_HISTORY.md` … 会話セッション単位の作業履歴
- `journal/docs/NEXT_TASK.md` … 次回セッションで着手するタスク
- `journal/CHANGELOG.md` … コード・製品バージョン単位の変更履歴（このファイルとは
  役割が異なる。両者の内容を不必要に重複させない）

## セッションの定義

- 1セッションとは、Claude Code Web上で新しく作成された1つの会話セッションを指す
- 「1つの明確な目的＝1セッション」を基本とする
- 同じセッション内で行う追加修正・表示調整・テスト・再修正は、すべて現在の
  セッション（同じS番号）内の作業項目として扱う
- 同じセッション内ではセッション番号（S番号）を変更しない
- 新しいClaude Code Webセッションが作成された場合だけ、セッション番号を1つ増やす
- セッション番号は`journal/docs/SESSION_HISTORY.md`で管理する

## 同一セッション内の運用ルール

- 細かな追加依頼ごとに`SESSION_HISTORY.md`を更新しない
- 細かな追加依頼ごとに`NEXT_TASK.md`を更新しない
- 細かな追加依頼ごとにコミットやPushを行わない
- 軽微な修正や試行錯誤の途中では、原則としてコミットやPushを行わない
- 追加作業の完了時は、変更内容とテスト結果だけを簡潔に報告する
- 管理ファイル（この4ファイル）の作成・更新だけでセッションを終了しない
- 管理ファイルを作成・更新しても、それだけでは次のS番号へ進めない

## セッション終了処理

セッション終了処理は、ユーザーが次のいずれかを明示した場合だけ実施する。

- 「このセッションを終了する」
- 「引継ぎを作成する」
- 「次のセッションへ移る」
- 「セッション終了処理を行う」

終了時にまとめて以下を実施する。

1. 必要に応じて`journal/docs/PROJECT_STATUS.md`を更新する
2. `journal/docs/SESSION_HISTORY.md`に今回のセッションを1件だけ追記する
3. `journal/docs/NEXT_TASK.md`を次回セッション用に更新する
4. 差分とテスト結果を確認する
5. 必要な変更をコミットする
6. リモートブランチへPushする
7. 未コミット変更と未追跡ファイルを確認する
8. 次回セッションのタイトルと開始プロンプトを提示する

## 既存内容の保護ルール

- 既存コード（`journal/*.py`, `journal/*.bat`）を無断で変更しない
- 既存ファイルを削除・移動・リネームしない
- `journal/CHANGELOG.md`を上書き・変更しない（変更が必要な場合は変更案のみ提示する）
- リポジトリ直下の`README.md`を変更しない
- 既存のGit履歴を変更しない（force push、履歴の書き換え等を無断で行わない）
- マージ・リベース・リセットを無断で実行しない
- APIキー・パスワード・認証情報をこれらの管理ファイルに記載しない
- 既存内容と新しいルールに矛盾がある場合は、無断で修正せず、矛盾内容と推奨対応を報告する
