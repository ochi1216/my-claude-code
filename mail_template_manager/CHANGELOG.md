# CHANGELOG — mail_template_manager

## VERSION 20260916_01

### 追加・修正

**ツールの新規立ち上げ。設計（Phase 1）を確定し、M0の実機プローブを実装した。**

定型メール（月次レポート等）をカードとして管理し、その月のSharePointフォルダ／ファイルの
リンクを自動解決してOutlookの下書きを組み立てるツール。本セッションでは**設計の確定**と、
**会社PCでしか確かめられないことを1回だけ測るための診断スクリプト（M0）**までを実装した。
本体（M1以降）は未着手で、M0の結果を見てから着手する。

**設計上、特に重要な判断を4点記録する。**

**1. 「アルゴリズム」をスクリプトではなく宣言的データとして保存する。**
越智さんの例1・例2は、抽象化すると「①対象期間を決める → ②その期間でSharePointの場所を
特定する → ③テンプレートに差し込む」の3段でしかない。これをPythonスニペット等のコードで
保存すると、GUIから安全に編集できず、壊れたときに原因も追えず、任意コード実行にもなる。
「変数バインディング表＋テンプレート文字列」として保存する方式に決めた。

**2. 「送信済み」を件名で照合してはいけない。**
当初案は送信済みアイテムを件名＋宛先で照合して送信を検出するものだったが、**越智さんは
送信前に必ず一言足し、件名も直す**。件名が変われば照合が外れ、送ったのに「未送信」と
表示される。**未送信バッジが一度でも嘘をつくと誰も見なくなり、本ツールが掲げる価値
（送り忘れ撲滅）が実装方式のせいで自壊する**。そこで `MailItem.UserProperties` に
`MTM_CardId` / `MTM_PeriodId` を埋め込む方式に変更した。これなら件名も本文も自由に
編集されて構わない。ただし `UserProperties` が使えるかは前例が無く未検証のため、
M0の項目[7]で測る。失敗した場合は「送信しました」チェックボックスによる手動遷移に切り替える
（自動化は減るが、嘘はつかない）。

**3. 社内実証記録の誤読を訂正した。**
`power_automate_safety_checkin/README.md:19` の「`Mail.Send` への管理者同意が必要」という
記録は、**Graphのアプリケーション権限の話であり、Power Automateのユーザー実行フローとは
別物**である。当初案ではこれを「Graph経由のメール送信は使えない」と一般化していたが、
過剰な一般化だった。この帰結として、M3（`schtasks`による定刻実行）の存在価値は相対的に
下がるため、M1の運用実績を見てからPower Automateとのハイブリッドと比較して要否を判断する。

**4. 時間の節約では正当化できないことを明記した。**
代替手段（`.oft` ＋ お気に入り ＋ PAリマインド）と比べた時間の節約は月2通で年16分にすぎない。
本ツールの唯一の存在理由は「**定型メールが増えたときに一覧・分類・棚卸しできること**」で
あり、3枚以下なら作らない方がよい。越智さんに確認したところ5〜10枚とのことで、Go と判断した。
この帰結として、M1の一覧画面の主役は「カード」ではなく「今月の提出状況」とする。

**M0プローブは、越智さんの実機時間を1回しか使わない前提で9項目を選んだ。**
特に `.Save()`（画面を開かない下書き保存＝M3の実現方式を決める）、`UserProperties`（上記2）、
署名HTMLの実物、日本語フォルダ名を含む長いURLの保持を測る。Graphの `/children` の汎用疎通は
`document_search_manager/DESIGN_NOTES.md` 3-6節で 2026-09-10 に実証済みのため**測らない**
（越智さんの時間を既知の確認に使わない）。

動作確認時の注意：

	本プローブはWindows・Outlook専用のため、本セッションの実行環境（Linuxコンテナ）では
	Outlookの実動作を再現できない。そのため `probe_outlook.py` は **win32com をトップレベルで
	import しない構造**にし、HTML組み立て・レポート整形・例外分離・認証情報の借用を
	開発環境でも検証できるようにした。
	`python3 -m py_compile` による構文チェックに加え、スタンドアロンの検証ハーネスで
	**62項目すべて合格**している。検証内容は、(1)リンクのHTMLエスケープ（属性を抜け出す
	細工が効かないこと）、(2)署名HTMLへの本文差し込み（`<body>` の内側に入ること・署名が
	残ること・本文が先に来ること・`<head>` の `<style>` を壊さないこと・`<body>` が無い場合や
	大文字 `<BODY>` の場合・閉じ忘れHTMLの場合）、(3)Graph共有URLのbase64url変換と復号、
	(4)総合判定（重要3項目のNGは「要再検討」でM1-βへ、それ以外のNGは「条件付きOK」で
	M1-αのまま、注意のみならOK扱い、件数の数え方）、(5)レポート整形（総合判定が本文より
	前に出ること・`[お願い]` が末尾に再掲されること・メタ情報の桁が**表示幅で**揃うこと）、
	(6)**例外が出ても最後まで走り切ること**（1項目目で例外を出しても2項目目が実行され、
	両方がレポートに載り、例外の型名と内容が結果に残ること）、(7)認証情報の借用
	（自分の設定を優先・`credentials_from` からの借用・大文字キー `TENANT_ID` への対応・
	借用先が無くても例外にならないこと）、(8)**安全性**（`ast` で構文木を解析し、`Send` /
	`SendAndSave` / `Submit` をどこからも呼んでいないこと、後始末で `Close` と `Delete` を
	呼んでいること、結果を UTF-8 BOM付きで書くこと）である。
	安全性の検証に文字列検索ではなく `ast` を使ったのは、docstring 内の説明文
	（「`.Send()` を呼ぶコードは存在しない」）に反応して偽陽性になったため。
	あわせて、Outlookが存在しないLinux上で実際に `probe_outlook.py` を実行し、
	全9項目が最後まで走り切ること、pywin32 未導入時に「再実行が必要です」と判定して
	`pip install pywin32` の手順を案内し、**結果ファイルの送付を依頼しない**こと
	（環境不備の結果を送っていただいても設計の判断材料にならず、往復が1回無駄になるため）を
	目視で確認した。

	**実機での確認をお願いしたい**：会社PCで `run_probe.bat` をダブルクリックし、
	(1)9項目が最後まで実行されること、(2)`probe_result_YYYYMMDD_HHMM.txt` と
	`probe_signature.html` の2ファイルができること、(3)結果ファイルをメモ帳で開いて
	文字化けしないこと（UTF-8 BOM付きで書いているため）、(4)作成されたメールが下書きフォルダに
	残っていないこと、(5)メールが1通も送信されていないことを確認いただきたい。
	結果の `[NG]` は問題ない（設計をそれに合わせるための調査であり、越智さんの追加作業は
	発生しない）。結果ファイル2つと、本文中の `[お願い]` への回答をいただきたい。
