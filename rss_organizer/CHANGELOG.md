# CHANGELOG — rss_organizer

## [20260801_01] - 2026-08-01

**追加ファイル:** `rss_organizer_20260801_01.py`（`20260708_02`からのコピー＋変更。旧版はそのまま残置。VERSION定数 `"20260801_01_01"`）
**変更ファイル:** `README.md`

ユーザーより「AI最先端フィード（Tab3）分が毎回大量に読み込まれてしまうので、ソースを限定したい」との要望があり対応。

**第1版（後に訂正）:** `AI_FEED_URLS` を20フィードから14フィードに削減（英語メディア5→3、論文・研究5→3、日本語メディア4→2）、`AI_FEED_ARXIV_MAX` を15→8に削減。除外基準はClaude Codeが重複性・AI専門度合いを独断で判断したもの。

**訂正（同日）:** ユーザーより「勝手に進めないでください」と指摘を受け、以下の通り修正:
- 英語メディア（3→5に復元）・AI企業・研究機関ブログ（6のまま）・日本語メディア（2→4に復元）は元の件数を維持することが確定。The Verge AI, Wired AI, Publickey, テクノエッジは全て復元。
- 論文・研究（現状5件: arXiv cs.AI/cs.LG/cs.CL/cs.CV, Papers with Code）と `AI_FEED_ARXIV_MAX`（現状15）は「要検討」。ユーザーが過去の実際の投稿数実績を確認してから判断したいとのことで、判断が出るまで元の値のまま据え置き。
- 過去実績データの取得を試みたが、リポジトリ内に実行履歴ファイルなし、本セッション環境からarXiv等への直接アクセスも不可のため実測データは提示できず、一般的傾向（未検証）の参考値のみ提示済み。
- 現時点で `rss_organizer_20260801_01.py` は、コメント（変更履歴の記述）を除き `20260708_02.py` と実質的に同じ設定値になっている。論文・研究フィードの最終構成は未決定であり、詳細は `docs/NEXT_TASK.md` を参照。

**最終決定（同日）:** ユーザーより実際の `ai_feed_history.json`（直近1週間・606件）の提供を受け、分析した結果:
- arXiv 4フィード（cs.AI/cs.LG/cs.CL/cs.CV）が全体の345件（57%）を占め、アクティブな日は1日あたり最大60件（＝`AI_FEED_ARXIV_MAX`15件×4フィードの上限に張り付き）取得されており、「毎回大量」の主因と判明。
- Papers with Codeは同期間で0件。Windows実機で `feedparser.parse()` を実行してもらったところ `bozo=True`、`SSLV3_ALERT_HANDSHAKE_FAILURE` でフィード自体が現在機能停止していることを確認。
- AI企業・研究機関ブログもOpenAI以外（Anthropic/DeepMind/Meta/Hugging Face/DeepLearning.AI Batch）は同期間0件だったが、今回のスコープ外のため変更せず（次回確認候補としてNEXT_TASK.mdに記録）。
- ユーザー判断により、**論文・研究カテゴリはarXiv4フィード・Papers with Codeとも取得を停止し、0件（`AI_FEED_URLS["論文・研究"] = []`）に確定**。`AI_FEED_ARXIV_MAX`定数自体は将来の再開に備えて残置（現状未使用）。
- 合わせて、GUIのフィード構成説明ラベル（空カテゴリの表示、arXiv上限の注記）が新構成で不正確になる問題を修正。
- 最終構成: 英語メディア5 / AI企業・研究機関ブログ6 / 論文・研究0 / 日本語メディア4 = 計15フィード（旧: 20フィード）。
