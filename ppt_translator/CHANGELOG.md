### 実機の出力で確認できたこと（実測）

- **英語の残骸:** 427ブロック中106個（25%）で、四角の外に元の文字のインクが残っていた。24枚中23枚。

- **原因は2つの合わせ技:** ① Geminiの箱が文字より小さく内側に寄っていた（ランダムなずれではなく、片側への偏り）。
  ② `_grow_while_background`（塗る範囲を広げる処理）は、広げる帯に背景色でない画素が12%以上あると止まる。
  箱が文字より小さいと、広げる帯に**自分の文字のインク**が入り、そこで止まってしまった
  （箱を縦に15%縮めると、広げる量は足りるのに33/40ブロックで止まる。広げる上限を35%→100%にしても塗り漏れは54.5%で不変）。

### 修正（この版）

- **文字の塊へのスナップ（塗り漏れ）:** 箱と重なるインクの連結成分（水平方向に少し膨らませて、字と字・行末の句読点をつなぐ）を辿り、
  その外接矩形まで四角を広げる。AIの位置に頼らず、画像の実際のインクから範囲を決める。極端に大きい塊（棒グラフ・罫線など）は無視し、
  隣のブロックの箱には入らない。文字枠（訳文の置き場所）は従来の広げ方のままで、四角だけが広がる。四角は全部貼ってから文字を貼る。
  標準ライブラリとPillowだけで実装した（分析では scipy を使ったが、依存を増やさないため書き直した）。
- **背景色の推定:** 「箱の内側の最頻色」から「箱の周囲（箱の高さの0.6倍ぶん）まで含めた最頻色」へ。箱が文字より小さいと内側の大半が
  文字の色になり、濃い帯の上の白いヘッダーの四角が白になっていた（実物のスライドで再現）。実物のスライド6・13で、
  濃い緑の帯・灰色の帯・縞々の行の背景色を、周囲まで含めた方式は正しく取り、内側だけの方式は箱が縮むと白を返した。
- **太字・寄せ:** Geminiに `bold`（太字か）と `align`（left/center/right）を返させ、反映する。中央寄せ・右寄せは、スナップで得た
  実際の文字の範囲を基準に文字枠を置く（左寄せは元の文字の左端、中央は元の中心、右寄せは元の右端）。
- **文字サイズ:** 上限の係数を1.25→1.1に緩め、基準の高さは「Geminiの箱」でなく「スナップで得た文字の実際の高さ」にする
  （実機で、出力サイズが元の文字の高さの中央値0.88倍に小さくなっていた）。原文が1行のブロックは、折り返す前に元の75%まで縮めて1行に収める
  （「ウェルビー/イング」のような折り返しを減らす）。
- **確認画面の初期値:** 「処理するスライド」の欄に、先頭の対象スライド1枚の番号を入れておく（全部を処理するときは欄を空にする）。
  実機では、おすすめした「まず1枚」が守られず、全24枚がそのまま処理された（初期値が空欄=全部だったため）。
- **デバッグ出力（既定オフ）:** 環境変数 `PPT_IMAGE_DEBUG_BOXES=1` のとき、出力ファイルの隣に `〜_boxes_debug.json` を作る。
  Geminiが返した箱の位置・行数・太字・寄せ、各ブロックを重ねたか（重ねなかった理由）、塗った範囲、文字サイズを**数値だけ**で保存する
  （**原文・訳文は含めない**。文字数だけ）。今回の実機の実行では生の箱を保存しておらず、原因を完全には切り分けられなかったため。
  ユーザーの了承を得て追加した。

- **挙動差**: `request_options={"timeout": 40}` は共通モジュールに同等の機能が無いため削除した。
  タイムアウトは `gemini_client.py` 側の固定値（直接15秒／プロキシ60秒）になる。遮断下では最初の
  バッチだけ直接呼び出しの15秒タイムアウトを待つぶん遅くなるが、一度失敗すると以降はプロキシ直行に
  なるため2バッチ目以降は影響しない（**仕様どおりの挙動であり、不具合ではない**）。
- **PowerPointの処理は1行も変更していない。** スライド走査・表セル／スピーカーノートの収集・
  run単位の書き戻し・進捗ウィンドウ・ファイル選択はそのまま。ASTによる関数単位のハッシュ比較で、
  13個の関数・クラス（`translate_ppt_document_thread` / `translate_super_fast_parallel` /
  `WordProgressWindow` / `select_file` / `is_translatable` / `get_logger` など）が旧版と
  **完全一致**することを確認済み。変更したのは `check_dependencies` / `init_gemini` /

### 既知の挙動（移行スコープ外。触っていない）

実機で気になったときに「移行のせいではない」と切り分けられるよう記録しておく。

- `translate_super_fast_parallel()` … チャンクが例外で失われたとき `[""] * batch_size` で埋めるため、
  最終チャンクだと翻訳結果の件数が合わなくなりうる。
- `WordProgressWindow` … PowerPointのツールなのにクラス名が `Word` のまま（Word版から流用した名残）。
  動作に影響はない。
- 出力ファイル名 … `target_language.split()[0].lower()` を使うため `_gemini_japanese.pptx` になる
  （`pdf_translator` の `_ja.pdf` のような2文字コードではない）。既存の出力名が変わると運用に影響
  するため、依頼が無い限り変更しない。
