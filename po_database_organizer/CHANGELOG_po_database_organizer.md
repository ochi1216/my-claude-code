# Changelog - po_database_organizer

バージョン番号はファイル名の日付_連番（例 `po_database_organizer_20260713_04.py`）に対応。

## v04 (20260713_04)

- アクセストークンをスキャン開始時に1回だけ取得して使い回していたのを、Graph APIリクエストのたびに取得し直すよう修正（MSALはキャッシュが有効なら即座に返すため速度への影響はない）。大規模サイトのスキャンが1時間を超えるとトークンの有効期限切れで401 Unauthorizedになり、残りのProject/Vendorが一切取得できなくなる（かつ失敗時は結果を保存しないため、古いスキャン結果がそのまま残ってしまう）問題への対応。po_pdf_mergeで先に見つかった同種の不具合を受けて調査・修正。

## v03 (20260713_03)

- 「PO一覧」を「1PO=1行（代表ファイルのみ）」から「1書類=1行」に変更し、旧「関連書類」シートの内容を統合。同一PO番号に複数の関連ファイル（改訂版等）がある場合は、その数だけ行を列挙するようになった。これに伴い旧「関連書類」シートは廃止。
- 「PO一覧」「未分類書類」の先頭列（A列）に `Project ID` を追加。
- マスタ用の「Projects」「Vendors」シートを廃止。Project IDを各行に直接埋め込む形にしたため、名寄せ用の別シートが不要になった。

## v02 (20260713_02)

- 「未分類書類」シートの「サブフォルダ(詳細)」列を削除。「PO関連フォルダ」列（ハイパーリンク付き）とファイル名自体のハイパーリンクで文脈が分かるため、重複していた列を整理。
- 以後、更新のたびにファイル名の日付_連番をインクリメントする運用を開始（`run_po_database_organizer.bat` が同一フォルダ内の最新版を自動選択する仕組みと対応）。

## v01 (20260713_01)

- 初版。SharePoint上のPOフォルダ（Project > Vendor > 書類）をGraph API（MSAL Device Code Flow）でスキャンし、PO番号を軸にしたカタログをExcel/JSONで出力する機能を実装。
- ファイル名が "PO" で始まるものだけを確実にPO本体として認識してPO番号を抽出し、それ以外は「未分類書類」として一覧化（無理な自動分類はしない方針）。
- 同バージョン内での修正:
  - `config.json` の `tenant_id`/`client_id` がテンプレートのプレースホルダーのままの場合、MSALの分かりにくいエラーではなく明確なメッセージで停止するよう修正。
  - Project/Vendor/ファイル名の各セルに、別列の「リンク」ではなくセル自体にハイパーリンクを直接埋め込む方式に変更。
  - Project > Vendor > **PO関連フォルダ**（実際のフォルダ階層の3階層目）の列を追加し、ハイパーリンクを付与（PO一覧・関連書類・未分類書類の各シート）。
