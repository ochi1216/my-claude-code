# Changelog - po_pdf_merge

バージョン番号はファイル名の日付_連番（例 `po_pdf_merge_20260713_07.py`）に対応。

## v10 (20260713_10) — 重要度高

- PO関連フォルダの下にさらにサブフォルダ（例:「Old Quotation」）があり、対象PDFがその中に置かれているケースで「ファイルが見つかりません」（404）になっていた不具合を修正。ユーザーがSharePoint上のフォルダ構成を直接確認して発見（`PO#8210198430_MRA1.0 Mask_DBH.pdf` が `PO関連フォルダ/Old Quotation/` の中にあり、`PO関連フォルダ` 直下ではなかった）。
- 従来はProject/Vendor/PO関連フォルダ/ファイル名の4列を単純に「/」で連結して相対パスを組み立てており、この間に想定外の階層があるケースを表現できなかった。「ファイル名」セルには元々、実際の正しいフォルダ階層を反映したハイパーリンク（po_database_organizerなら実際のGraph API webUrl、po_query_importならクエリのPath列から再構築したURL）が埋め込まれているため、まずこちらからdrive相対パスを直接復元するよう変更し、階層数によらず正しく解決できるようにした（ハイパーリンクが無い場合のみ従来の4列連結にフォールバック）。

## v09 (20260713_09)

- ダウンロードパス組み立て時のURLエンコードが過剰で、フォルダ名・ファイル名に `(` `)` `,` `'` `&` `.` `;` `=` `!` などの記号を含む一部のファイルで「ファイルが見つかりません」（404）になっていた不具合を修正。従来は `quote(path, safe="/")` で `/` 以外の記号を全てパーセントエンコードしていたが、`po_query_import` でのURL再構築調査時に判明した実際のGraph API由来URLの安全文字セット（`/()',.&+;=!$` はエンコードしない）に統一した。実際に失敗していたケース（Vendor名に `Co., Ltd` を含むパス）で確認・修正。
- なお、これはエンコード起因の404を解消するものであり、対象フォルダ自体がSharePoint上で既にリネーム・移動されている場合の404までは解消しない。

## v08 (20260713_08)

- 「PO関連フォルダ」列が空欄の行（PO一覧のフォルダ階層がVendor直下、またはプロジェクト直下で、PO関連フォルダに相当する3階層目が無いPDF）で「PO関連フォルダ または ファイル名 が空欄です」というエラーとなり、PDFの中身が一切解析されずスキップされていた不具合を修正。特に `po_query_import` で作成したPO一覧には、この形のファイルが少なからず含まれる（実データでの検証では該当101件が全てこのエラーで失敗していた）。
  - Vendor直下（PO関連フォルダ空欄・Vendor列は実フォルダ名）: `Project/Vendor/ファイル名` としてダウンロードを試みる。
  - プロジェクト直下（Vendor列が `(プロジェクト直下)`）: `Project/ファイル名` としてダウンロードを試みる。
  - 「ファイル名」列自体が空欄の行のみ、従来どおりエラーとして扱う。
  - この修正は「PO明細(PDF抽出)」シートへの新規追記のみを行い、既存行・既存のハイパーリンクの位置は変更しない（新しく処理できた行の分だけ末尾に追記される）。

## v07 (20260713_07)

- アクセストークンを起動時に1回だけ取得して使い回していたのを、リクエストのたびに取得し直すよう修正。処理に時間がかかりトークンの有効期限（通常1時間程度）が切れると発生していた「401 Unauthorized」でのダウンロード失敗に対応（MSALはキャッシュが有効なら即座に返すため速度への影響はない）。
- 途中から再開できる機能を追加。
  - `--start-row N` で開始行を明示的に指定できる（例: `--start-row 107`）。
  - 既に「PDFヘッダーPO番号」が入力済みの行（前回成功した行）は自動的にスキップする。前回出力した `_detail.xlsx` をそのまま入力に指定すれば、エラーで止まった行や未処理の行だけ再処理できる。
  - 「PO明細(PDF抽出)」シートが既にある場合は前回分を保持したまま追記し、新たに（再）処理した行だけハイパーリンクを更新する。

## v06 (20260713_06)

- 処理速度の改善。入力Excelの「未分類書類」等、本ツールが触れない他シート（数千行規模になりがち）を読み込み直後に破棄するようにした。従来は10件ごとの中間保存のたびにファイル全体（未分類書類を含む）を書き直しており、行数が多いとこれが処理時間の大半を占めていた（実測でシート有無により保存1回あたり約18倍の差）。ハイパーリンク自体は軽い処理で速度への影響はごく僅か。
- 「PO一覧」の新規列の並びを v05以前の `PDFヘッダーPO番号` → `ヘッダー接頭辞` の順に戻した（v05でヘッダー接頭辞を先頭にしたが、視認性の観点から差し戻し）。

## v05 (20260713_05)

- po_database_organizer v03のExcelフォーマット変更（「PO一覧」が1書類=1行に、列名「代表ファイル」→「ファイル名」）に対応（旧列名「代表ファイル」にもフォールバック対応）。
- 新規列の並びを「ヘッダー接頭辞」→「PDFヘッダーPO番号」の順に変更。
- 「PO一覧」の `PDFヘッダーPO番号` セルから「PO明細(PDF抽出)」の該当PO番号・Line 00010行のA列へジャンプするハイパーリンクを追加。
- 「PO明細(PDF抽出)」の `PO番号` セルから「PO一覧」の対応行の `PDFヘッダーPO番号` セルへジャンプするハイパーリンクを追加（双方向）。リンク先は値の一致ではなく処理元の行番号で対応させているため、同一PO番号が複数行ある場合（改訂版等）も、それぞれ正しい行同士でリンクする。

## v04 (20260713_04)

- 1ページ目冒頭のタイトルが "Purchase Order" ではなく "Changed Purchase Order"（変更発注書）の場合にも対応。実際に見つかったタイトル文字列を「PDF種別」列として記録。
- 「PO明細(PDF抽出)」シートにも「ヘッダー接頭辞」列を追加。

## v03 (20260713_03)

- 「PDFヘッダーPO番号」が数字部分のみになっていた不具合を修正し、国コード+拠点コード（例 HK64, CN69, JP68）を別列「ヘッダー接頭辞」として復活。
- Vendor列とPO関連フォルダ列が同名になっている行でファイルが見つからない場合、フォルダの重複セグメントを1つ省いたパスで再試行するフォールバックを追加。

## v02 (20260713_02)

- 入力Excelファイルをコマンドライン引数で指定する代わりに、起動時にファイル選択ダイアログ（tkinter、サブプロセス経由で起動）が開くよう変更。
- 出力ファイル名を `<入力ファイル名>_merged.xlsx` から `<入力ファイル名>_detail.xlsx` に変更。
- 起動用バッチファイル `run_po_pdf_merge.bat` を追加（`po_pdf_merge_*.py` の最新版を自動選択）。

## v01 (20260713_01)

- 初版。po_database_organizer が出力した「PO一覧」Excelを読み込み、各行のPO本体PDFをSharePointから直接ダウンロード（Graph APIのパス指定ダウンロードを使用し、ブラウザ・MCAS確認画面は経由しない）し、ヘッダーPO番号・発注金額・明細行数を抽出して「PO一覧」シートに統合、「PO明細(PDF抽出)」シートを追加。
- 全件処理を10件ごとに一時停止し、「次の10件へ進む」「最後まで自動で進める」「中断して保存」を選択できる進捗管理を実装。
