# AIエージェント化 統合プラン v8（v7レビューFAILを受けて修正）

## 0. 定義
「AIエージェント化」= **①集める→②AIが要約・提案→③人間が承認→④承認分だけ反映→⑤履歴** の循環を既存ツールに通すこと。外部SaaS送信なし・新規IT権限なし・Outlook(win32com)前提・自動送信なし。
**最初の段階で越智さんが「週次の要約と改善提案」を体感できる順序にする（v5 M1対応）。**

## 1. 捨てる
Outlook MCP/M365、Notion、Slack、月曜9:00自動起動、AI検証エージェント（→決定論）、全数AI関連度判定、全自動更新、新規分類profile json、カテゴリ名の新設/改名、プロンプト文面変更、アクションタブの「対応済み候補」判定（v5 B3: アクション取得は include_sent=False(2341)で原理的に判定不能、同等判定はコックピットv2に既存(4545)＝そちらを使う）。

## 2. 共通ルール
- 文字数: 1行サマリ≤100字、エグゼクティブサマリ≈300字（検出320字）。NFC正規化後len()、改行・前後空白除外、100字ちょうど許容。1行は切らず再圧縮1回→失敗は原文＋「超過」バッジ。エグゼクティブは「。」で各300字以内の段落に分割、句点なし/1文300字超は警告のみ。
- 承認の書込先は既存の `ai_correction_rules`（プロジェクト/スタッフ解析にのみ効く）と `excluded_domains` の2つだけ。

## 3. 段階

### P0 帰属率の実測（診断スクリプト・本体非改変）
- `diagnose_weekly_attribution.py`（diagnose_archive.py と同じ扱い、本体のバージョン管理対象外、読み取り専用）。
- 過去7日について、(a) プロジェクトごとに既存 get_project_mails(folder,7) 相当、(b) スタッフごとにスタッフ俯瞰と同じ search_mails_fast 2本立て（11520-11549: from=sender条件、to/cc=本文キーワード、strict_mode=False、include_sent=True、SEARCH_ALIASES適用）。get_staff_mails(3489)は呼び出し元なしのデッドコードで日付書式も不正なため使わない、(c) 受信トレイ直下 get_relevant_mails_for_period(7) を取得し、件数と「どこにも帰属しないスレッド数」を表示。本文・件名は出力しない（件数のみ）。プロジェクトごとに「フォルダ未発見／0件／N件／1000件打切り」を区別して表示（3204で未発見も[]になるため、存在確認を別途行う）。各取得の所要時間も計測し、P1の許容時間（目安3分）を判断する。
- 越智さんが実機で1回実行→帰属率を見てP1の形を決める。**分岐基準（事前に固定）: 帰属率50%未満、または所要時間3分超なら** P1 は「全体＋ドメイン統計」に縮小し、P3bは「ドメイン除外」のみで開始。

### P1 週次コーチング（読み取り専用・最小構成）← 最初に体感
- 新タブ「🧭 週次コーチング」（notebookはインデックス参照なし＝末尾追加は安全、確認済み）。
- 取得と帰属は**俯瞰タブと同じ既存経路を再利用**（v6 B1）: プロジェクトは get_project_mails(folder,7) をプロジェクトごと、スタッフはスタッフ俯瞰(11520-11549)と同じ検索条件を作る純粋関数 `staff_search_conditions(staff_name, days, flags)`（SEARCH_ALIASES込み、Linuxで単体テスト可）を新設して search_mails_fast に渡す。対象者は project_knowledge["staffs"] のキー、flags は from/to/cc すべてTrue固定、名前の正規化(capitalize)も関数に含める。本文キーワード一致は署名等で過剰帰属し得るため、P0でスタッフ別件数を確認。スタッフ俯瞰タブ側の既存コードはこの段階では変更しない（条件の二重定義は、P1納品後に俯瞰タブを同関数へ寄せる別リビジョンで解消）、加えて受信トレイ直下を get_relevant_mails_for_period(7)。conversation_id で重複除去、帰属はプロジェクト優先→スタッフ→未帰属。検索回数はプロジェクト数＋スタッフ数×2＋1回（本文キーワード検索は重い、進捗表示あり）。帰属判定は「7日以内に受信したメールの conversation_id 単位」に限定し、スタッフ検索で混ざる送信済み・スレッド展開分は帰属の根拠にしない（v7 M3）。
- AI入力上限（v6 M1）: 1スレッド=件名＋最新メール本文（_clean_body_text(2917)は改行整理のみで引用除去なし）の冒頭500字、1回のAI入力は合計30,000字まで（既存の30000字慣行に合わせる）。超過時は帰属先ごとに要約→全体要約へ統合（呼び出し回数は帰属先数＋1）。画面に「AI呼び出し予定 N回」を事前表示。
- 出力HTML: (a) 全体エグゼクティブサマリ（≈300字×最大3段落）、(b) 帰属先ごとの1行サマリ（≤100字）、(c) 送信者ドメイン別 件数・未読数、(d) 帰属先ごとの「その他」比率と件名n-gram上位、(e) 改善提案候補（書込なし）。
- 提案候補のJSONスキーマをP1で確定しP3bでそのまま使う（v6 M2）: {id, kind: "rule"|"domain_exclude", target_kind: "project"|"staff"|null, target_name, text, evidence:{ngrams:[...], domains:[...], thread_count}}。
- キャッシュは analysis_cache/weekly_coaching/{ISO年}W{ISO週}.json。アクションタブのキャッシュとは共有しない（v6 m2）。
