# PDF Translator (Gemini API)

英語などのPDFをGoogle Gemini APIで翻訳し、レイアウト（文字の位置・フォントサイズ・
文字色・背景）をできる限り保持したまま翻訳版PDFを生成するデスクトップツール（tkinter GUI）。

`ppt_translation_20260309_03.py`（PowerPoint Gemini 翻訳ツール）のUI／進捗表示／
Gemini呼び出しロジック（自動モデル検出・タイムアウト・リトライ・フェイルファスト・
ロギング）を踏襲し、PDF向けにテキスト抽出・書き戻し部分を新規実装したもの。

## 必要要件

- Python 3.9以上
- 共通モジュール `gemini_client.py`（[gemini-common-tools](https://github.com/ochi1216/gemini-common-tools)）
- 以下の環境変数のうち**どちらか一方以上**
  - `GEMINI_API_KEY` … Gemini APIキー（直接呼び出し用）
  - `GEMINI_PROXY_URL` … 自宅PCプロキシのURL（直接呼び出しが失敗したときのフォールバック先）

### Gemini API の呼び出し経路について（20260812_01 以降）

会社PCからGemini APIへの直接アクセスが遮断された（2026-08-10頃）ため、共通モジュール
`gemini_client.py` 経由で呼び出す方式に移行した。**まず直接呼び出しを試し、失敗したら自宅PCの
プロキシへ自動的にフォールバックする**ため、ツール側で経路を意識する必要はない。

- `gemini_client.py` は上位ディレクトリの `common` フォルダから自動的に探される
  （会社PCの配置では、本スクリプトから見て「2つ上」の `PythonScripts\common\`）。
  別の場所に置いている場合は環境変数 `GEMINI_COMMON_DIR` でフォルダを指定できる。
- 使用モデルは `gemini-2.5-flash` 固定。環境変数 `GEMINI_MODEL` で変更できる
  （20260722_08 までは起動時に使用可能モデルを自動検出していたが、これはネットワーク
  アクセスを伴い遮断下では起動すらできなくなるため廃止した）。
- 遮断されている環境では、**最初のバッチだけ**直接呼び出しのタイムアウト（15秒）を待つぶん
  遅くなることがある。一度失敗すると以降はプロキシ直行になるため、2バッチ目以降は影響しない。
  これは仕様どおりの挙動で、不具合ではない。


### 日本語→英語など、CJKから欧文への翻訳について（20260821_01 以降）

本ツールは当初、英語→日本語を想定して作られていた。20260821_01 で逆方向（日本語→英語）
にも対応するため、次の点を修正している。

- 背景色の判定を作り直し、**翻訳文が背景と同じ色で塗り潰されて読めなくなる**不具合を解消した。
- 「企業」「震度」のような**2文字の日本語**も翻訳対象に含めるようにした（英語の2文字以下は
  従来どおり除外する）。
- 翻訳文に「①②③」「※」などが残っていても、**"?" に化けずに表示される**ようにした。
- 中央寄せ・太字を保持するようにした。
- 同じ段落が行ごとに分断されて訳されるのを防ぐため、連続する行をまとめて1文として翻訳する。

**注意（原理的な限界）**: 日本語を英語にすると文字数が**およそ2.6倍**に増える。固定
レイアウトのPDFに可変長の翻訳文を必ず収める一般解は存在しないため、元から余白の少ない
欄では文字が小さくなったり、はみ出したりすることがある。これは実装の不具合ではなく、
PDFという形式そのものの制約である。余白に余裕のある資料ほどきれいに仕上がる。

## セットアップ手順

### Windows（バッチファイルで起動する場合）

1. 環境変数を設定する（コマンドプロンプトで実行後、一度開き直す）。
   **どちらか一方だけでも動作する**（プロキシ専用構成も可）。

   ```
   setx GEMINI_API_KEY "your-api-key"
   setx GEMINI_PROXY_URL "https://xxxx.ngrok-free.dev"
   ```

2. `run_pdf_translator.bat` をダブルクリックする。初回は仮想環境(venv)の作成と
   依存パッケージのインストールが自動実行される（2回目以降は起動のみ）。
   フォルダ内に `pdf_translator_yyyymmdd_NN.py` が複数存在する場合は、
   ファイル名が最も新しいもの（＝最新バージョン）を自動的に起動する。

### 手動セットアップ（macOS/Linux/Windows共通）

1. 依存パッケージをインストールする。

   ```
   pip install -r requirements.txt
   ```

2. 環境変数を設定する（`GEMINI_API_KEY` / `GEMINI_PROXY_URL` のどちらか一方以上）。

   ```
   # macOS/Linux
   export GEMINI_API_KEY="your-api-key"
   export GEMINI_PROXY_URL="https://xxxx.ngrok-free.dev"

   # Windows (PowerShell)
   setx GEMINI_API_KEY "your-api-key"
   setx GEMINI_PROXY_URL "https://xxxx.ngrok-free.dev"
   ```

3. 共通モジュール `gemini_client.py` を、上位ディレクトリの `common` フォルダに配置する
   （または環境変数 `GEMINI_COMMON_DIR` で場所を指定する）。

4. スクリプトを実行する（`pdf_translator_yyyymmdd_NN.py` の最新版）。

   ```
   python pdf_translator_20260821_01.py
   ```

### 使い方

1. 「ファイル選択」から翻訳したいPDFを選び、翻訳先言語（日本語／英語／中国語簡体字）を
   選んで「翻訳開始」を押す（「表・グラフに重なるテキストを翻訳しない（安全重視）」は
   既定でOFF＝翻訳する。より安全性を優先したい場合のみONにする）。

2. 完了すると同じフォルダに `元ファイル名_ja.pdf`（英語翻訳なら `_en.pdf`）のように、
   末尾2文字の言語コード付きで保存される。

## 処理の仕組み（20260821_01 時点）

1. PyMuPDF (`fitz`) で各ページのベクター図形（罫線）を解析し、線分同士が実際に交差して
   いるかどうかでクラスタリングして「表のグリッド（セル境界）」を検出する。単に
   ページ内の全水平線・全垂直線を1つの座標集合として扱うと、離れた場所にあるグラフの
   辺まで表の列線と誤認識してセルがズレるため、実際に交差する線分だけを同じ表とみなす。
2. テキストはスパン単位（PyMuPDFの「ブロック」単位より細かい、フォント情報を持つ最小
   単位）で抽出し、罫線グリッドのセル矩形に収まるものはセル単位でグループ化する
   （表の同じ行にある隣接セルの文字が1つに混ざらないようにするため）。セルの外側に
   ある自由配置のテキストは、従来通りブロック単位（≒段落）でグループ化する。
3. 抽出したテキストを10件ずつバッチにまとめ、Gemini APIへ並列（最大3スレッド）で
   翻訳リクエストを送信する。呼び出しは共通モジュール `gemini_client.py` 経由で行い、
   直接呼び出しが失敗した場合は自宅PCのプロキシへ自動的にフォールバックする
   （20260812_01 以降）。バッチごとに最大3回リトライし、3バッチ連続でエラーになった
   場合は処理を強制中断する。
4. 表セルは罫線から検出した実際のセル矩形の内部だけを墨消し（redaction）し、罫線
   そのものには一切触れない。墨消し時は `images`/`graphics` を保護するオプションを
   指定し、矩形に重なる罫線・画像・チャート図形を一切消去・上書きしない。
5. 翻訳文は、罫線とテキストの間隔から推定した元の寄せ（左/中央/右）で、フォントサイズを
   自動縮小しながら再配置する。
6. 罫線グリッドとして認識できない図（チャートの凡例・軸ラベル等）に重なるテキストも、
   既定では翻訳する（v03までの墨消し破壊バグを修正済みのため）。翻訳網羅性より安全性を
   最優先したい場合は、GUIの「表・グラフに重なるテキストを翻訳しない」をONにすると、
   その部分は原文のまま保護される。
7. 日本語／中国語（簡体字）／韓国語はPyMuPDF内蔵のCJKフォント（`japan` / `china-s` /
   `korea`）を使用するため、追加のフォントファイルは不要。

## 既知の制限（技術的な原理限界。100%保証はできない領域）

- **スキャン画像PDF（テキストレイヤーなし）は非対応。** OCR機能は今回のスコープ外。
- 罫線で囲まれていない自由配置の図（チャートの凡例・軸ラベル等）に重なるテキストも
  既定では翻訳される。可変長の翻訳文を固定レイアウトの図形に安全に収める一般解は
  存在しないため、狭い図形の中の文字などでは稀にレイアウトが窮屈になることがある
  （実装のバグではなく、PDFという形式そのものの制約）。気になる場合は「表・グラフに
  重なるテキストを翻訳しない」をONにすると、その部分は原文のまま保護される。
- 表セル以外の自由テキスト（段落等）は、1つの文が複数ブロックに分割されている場合に
  文脈が失われ、不自然な訳になることがある（20260821_01で、同一段落と判断できる連続行は
  まとめて翻訳するようにしたため大幅に減ったが、判断できない配置では依然として起こりうる）。
- 表セル以外の自由テキストの背景色は、矩形の周囲12点をサンプリングした多数決による
  近似のため（20260821_01で4点から増やした）、グラデーション等では完全には一致しない
  場合がある。
- 翻訳文が元の矩形に収まりきらない場合、フォントサイズを4ptまで自動縮小するが、
  それでも収まらない場合ははみ出したまま挿入される（`translation_debug.log` に警告記録）。

## トラブルシューティング

- **`Gemini認証情報が設定されていません`**: `GEMINI_API_KEY` と `GEMINI_PROXY_URL` の
  どちらも設定されていない。どちらか一方を設定した後、ターミナル／コマンドプロンプトを
  **開き直してから**実行する（`setx` は起動済みのウィンドウには反映されない）。
- **`Gemini共通モジュール(gemini_client.py)を読み込めませんでした`**: エラーメッセージに
  「探索したパス」が表示されるので、そこに `gemini_client.py` を置くか、環境変数
  `GEMINI_COMMON_DIR` でフォルダを指定する。
- **翻訳の最初のバッチだけ極端に遅い**: 直接呼び出しのタイムアウト（15秒）を待ってから
  プロキシへ切り替えているため。2バッチ目以降は速くなる（仕様どおりの挙動）。
- **`対象のPDFファイルが別のアプリで開かれています`**: PDF閲覧ソフトで対象ファイルを
  閉じてから再実行する。
- **`Gemini APIへの通信が3回連続で失敗しました`**: ネットワーク接続、またはAPIの
  レート制限を確認する。詳細は `translation_debug.log` を参照。
