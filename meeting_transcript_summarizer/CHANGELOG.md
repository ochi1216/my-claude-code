# Changelog

## 20260716_04

- 要約(議事録)にHTML形式(`summary.html`)を追加。Markdown形式は表形式のアクションアイテム等が読みづらいとのフィードバックを受け、見出し・リスト・表を装飾したHTMLを同じ要約データから生成するようにした。
- 処理完了時、生成した`summary.html`を既定のブラウザで自動的に開く機能を追加(`webbrowser`標準ライブラリを使用)。ブラウザが開けない環境でもパイプライン自体は失敗させず、ログに理由を表示するのみとした。
- HTML出力はユーザー入力(会議内容由来のテキスト)をエスケープしてから埋め込むようにした。

## 20260716_03

- 実機での動作確認で、1時間の会議録画に対し約10分程度しか文字起こしが出力されない不具合を修正。原因は、クラウドモードで音声全体を1回のGemini API呼び出しで逐語文字起こしさせていたため、出力トークン上限または長い単調な書き起こしをモデルが自主的に切り上げる挙動により、途中で打ち切られていたこと。
  - クラウドモードの音声を`chunk_minutes`(既定10分)単位にffmpegで分割し、チャンクごとに個別にGeminiへ送信・文字起こしする方式に変更。各チャンクの結果は絶対時刻に変換して結合する。
  - `gemini_max_output_tokens`設定を追加し、各チャンクのGemini呼び出しに明示的な出力上限を指定できるようにした。
  - チャンクをまたいだ話者ラベルの継続性を高めるため、直前チャンク末尾の文字起こしをヒントとしてプロンプトに含めるようにした(完全な一致は保証されない旨をREADMEに明記)。
  - GUIの進捗バーがチャンクの処理進捗に応じて滑らかに進むようにした。
- 主な言語(日本語/English/自動判定)をGUI上のラジオボタンで指定できるようにした。クラウドモードはGeminiへのプロンプトに言語ヒントとして反映し、ローカルモードはfaster-whisperの`language`引数に直接渡すことで、認識精度の向上を狙う。

## run_meeting_transcript_summarizer.bat 修正(20260716)

- バッチファイルが起動しない不具合を修正。原因は改行コードがLF(Unix形式)になっており、Windowsのcmd.exeが複数行にまたがる`if...else`ブロックを正しく解釈できなかったこと。
- 改行コードをCRLFに変換し、あわせて多段の`if...else`ブロックを`goto`によるフラットな分岐に書き直し、改行コードの違いによる解析崩れが起きにくい構成にした。

## 20260716_02

- 実機での動作確認で、Gemini APIの文字起こし応答が想定書式(`[分:秒] 話者A: 発言`)と完全一致しない場合に、内容が解析できず「Geminiの文字起こし結果を解析できませんでした」という原因不明のエラーで停止する不具合を修正。
  - パーサーを多段フォールバック化: 時刻付き行 → 話者のみの行(時刻なし) → 直前セグメントへの追記 → 新規セグメントとして保持、の順で可能な限り情報を失わないようにした。
  - コードブロック(` ``` `)や太字(`**`)などのMarkdown装飾、全角/全角コロン、`HH:MM:SS`形式の時刻表記にも対応。
  - クラウドモードでは、Geminiの応答全文を`transcript_raw_gemini_response.txt`として出力フォルダに常に保存するようにし、書式の想定外パターンを後から確認・調整できるようにした。
  - 応答が完全に空だった場合は、finish_reason(安全フィルタや長さ超過など)と応答プレビューをエラーメッセージに含めるようにした。
