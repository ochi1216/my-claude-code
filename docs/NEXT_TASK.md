## Current Objective

緊急地震速報で大分県・大阪府・東京都に震度5以上の速報が出た場合に、
緊急連絡網の18名のスタッフへ安否確認を自動送信し、各スタッフが
「無事/被災」「職場/自宅」「出社可能/出社不可能」の3項目をクリックで選択したら、
即座に上司3名へ通知される仕組みを、Microsoft 365環境を前提として構築する。

このセッションで新規導入し、同じセッション内で最初の実作業（自動送信機能の
プロトタイプ実装）まで進める。

- スタッフ向け回答フォーム（3項目・クリックで選択）
- 回答送信時の上司3名への即時通知（Microsoft Graph API経由を想定）

## Task

1. `emergency_alert_tool/` フォルダを新規作成し、既存ツールのバージョン管理規約
   （`ツール名_yyyymmdd_連番.py`、`README.md`、`CHANGELOG.md`、
   `requirements.txt`、`config.example.json`）に合わせて実装する。
2. 震度・対象都府県のトリガー判定ロジックを実装する。

6. 上記についてpytestによる自動テストを作成し、実行する。

- 3項目クリック選択の回答フォームが実装されていること
- 回答送信時に上司3名への通知処理が即座に実行されること
- 既存の他ツール・他機能に意図しない影響がないこと
- 必要な自動テストが実施され、結果が報告されること

## Required Tests

- 震度閾値・対象都府県によるトリガー判定のユニットテスト

## Known Risks

- 緊急地震速報の実データ取得元APIのスキーマは、本セッション環境から
  外部ドキュメントへアクセスできなかったため、既知情報を基にした
  想定実装であり、実データでの検証が別途必要。
- Microsoft 365テナントでの実際のGraph API疎通（アプリ登録・権限・
  管理者同意等）は本セッションでは検証できないため未確認。
- 回答リンクのトークン方式は簡易実装であり、なりすまし対策として
  Azure AD SSO等への強化を本番導入前に検討する必要がある。
