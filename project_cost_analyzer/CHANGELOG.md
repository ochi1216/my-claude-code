# CHANGELOG — project_cost_analyzer

## [20260722_01] - 2026-07-22

**追加ファイル:** `project_cost_analyzer_20260722_01.py`, `requirements.txt`, `README.md`, `run_dashboard.bat`

初版。Project CostのKOB1シート（SAPプロジェクトコスト実績明細）を読み込み、プロジェクト単位で
コスト分析を行うStreamlitダッシュボードを新規作成。

- Supabase等の外部サービスへデータをアップロードする方式を検討したが、社内の機密性の高い
  コストデータであることと、環境の自動判定（安全分類器）が外部への一括データ送信をブロック
  したことから、ローカル環境で完結する構成（Excel直接読み込み→ローカル集計→Streamlit表示）
  に方針転換した
- Project Name / Fiscal Year / Project status / Cost Category での絞り込み、プロジェクト別・
  期間別・Cost Category別・Cost Element別・Function別の集計、明細テーブル表示、Excel出力に対応
- Windows用起動バッチ`run_dashboard.bat`を追加。フォルダ内の`project_cost_analyzer_*.py`を
  ファイル名降順（`dir /o-n`）で判定し、最新リビジョンを自動的に起動する（バージョンアップ時に
  バッチファイル自体の書き換えは不要）

## [20260722_02] - 2026-07-22

**追加ファイル:** `project_cost_analyzer_20260722_02.py`（`20260722_01`からのコピー＋機能追加。旧版はそのまま残置）

元データが18MB・8万行超あり、Excelパースに15〜17秒かかっていた。今後頻繁に修正・再起動を
繰り返す運用を見込み、ユーザーより「元データに変更がなければ次回起動を高速化したい」との
要望があり対応:

- パース結果を「元ファイルの隣（パス指定時）」または「OS一時フォルダ（アップロード時）」に
  `.kob1_cache/` としてpickle保存し、元ファイルのパス・更新日時・サイズが変わっていなければ
  次回起動時にそこから読み込む（実測: 初回15〜17秒 → ツール再起動後のキャッシュ利用時は約2.5秒）。
  キャッシュはリポジトリ外に置き、機密データが誤ってGit管理下に入らないようにしている
- 同一Streamlitプロセス内では`st.cache_data`により、フィルタ操作のたびの再読み込みも回避する
  （実測: 約1秒）
- 元データを更新すると更新日時・サイズの変化により自動的にキャッシュが無効化される。古い
  キャッシュファイルは新しいキャッシュの保存時に自動削除し、ディスク容量の圧迫を防止
- サイドバーに「キャッシュを無視して再読み込み」チェックボックスと、キャッシュ利用状況・
  保存先の表示を追加
